# 记忆

## 五个层

**常驻**是每轮开局先读的那一页：`memory/常驻.md`。里面只有四样东西——上一轮停在哪、手上没结的活（队列和计划里挂着的，最多五条）、关于用户的几条事实、最近五条教训的标题。总字数硬顶 2000，由 `recall.py build` 生成，别手改。它不存新内容，只把别处的关键行摘过来；丢了大不了重跑一条命令。

**流水**是正本。一件一事，日记体，文件名带时间（`YYYYMMDD_HHMM_标题.md`），正文固定两段：`## 他说了啥`、`## 我心里`。只追加，不改历史，要改就写新件并在里面写「取代」。

**事实**是一句到现在还成立的话，一行一张卡：主体、谓词、值、时间、来源、来源类型、置信度、验证、生效、失效、取代。双时相，被顶掉的卡标失效日期和原因，不删。每张卡还有 `hash`（主体加谓词加值的内容指纹，去重用）、`last_used`（最后一次被引用或召回的时间）、`decay_applied`（已扣过几个 30 天）。

**向量**是 `memory/向量.jsonl`，一行一件的嵌入。它只负责把候选捞回来，不参与判域，也不当正本，删了能重嵌。

**教训**是 `运行/教训.md`，一条一行：日期、被现实推翻的判断、后来怎么改的。常驻页只取最近五条的标题，正文留在这里。

另外两个不算层，是派生物：**待记**是每回合的原料，只增不删，单文件 512KB 滚动，不进检索，只喂给整理；**状态**是件数、最后写入、五条续点，丢了可以从流水重建。

## 四层压缩

会话原文 → 草稿（一问一答各截一段）→ 流水（300 到 3000 字节）→ 事实卡（一句话）。

每往下一层，丢掉工具参数和输出（除非里面有结论）、试错过程（除非踩成坑）、客套、重复。留下决定和理由、带出处的数字、坑、承诺和未结的事、原话里值得留的那几句。

判据只有一条：换一个会话的 agent，只看常驻页和这一层，能不能接着干。能，就够；不能，说明丢多了。

## 写一件流水

```bash
core.py store --title "标题" --said "用户说的" --heart "心里的反应" \
  --source "会话id 或 件名" --domain 决策 --salience 4
```

`--source` 必带，不写来源的件等于没出处。`--domain` 只从白名单里选：环境、运维、架构、决策、项目、教训、未判。拿不准写「未判」，不硬凑。「我心里」至少 15 字，写反应，不写汇报腔。

## 续点与常驻

续点只装未结的事：卡在哪、下一步、必须知道的参数。已经做完的不进续点，进流水。写不出续点，等于这一场没收工。

`状态.json` 里保留最近五条续点。`recall.py build` 把它们、队列里没结的单、`domain=用户` 的事实卡、最近五条教训压成一页；`dream` 第 10 步会重建它，所以每天自动是新的。

```bash
recall.py build   # 重建 memory/常驻.md
recall.py show    # 打印出来看
```

## 事实卡

```bash
fact.py add --subject 这台机器 --predicate 型号 --value "示例值" \
  --verify "怎么验的" --source-type tool
fact.py check     # 找该验证的、同键冲突的、内容重复的
fact.py cite F0001   # 引用一次，置信度 +0.02
fact.py decay     # 满 30 天没用的有效卡乘 0.9
fact.py retire F0002 --reason "被新卡取代"
```

新增时如果同一主体加谓词已经有有效卡：值一样返回 NOOP；值不一样，旧卡标失效、写「取代」和 `superseded_by` 指向新卡，再落新卡。`check` 输出总数、有效数、未验证数、无来源数、同键冲突数、内容重复数。

置信度按来源类型给初值：抽取 0.4、工具 0.5、人给 0.8。被 `cite` 一次加 0.02，上限 1.0；满 30 天没被引用或召回就乘一次 0.9，扣过的记在 `decay_applied` 里，不会重复打折。老卡没这些字段，读的时候按默认值补：置信度 0.4，hash 现算，`last_used` 回落到创建时间。

事实卡宁可不抽，也别抽错。抽取器只用短句和固定连接词，长从句、疑问句、带情态动词的一律丢。

## 检索

三个入口，都带硬上限：

```bash
core.py search "词" --limit 5     # ≤5 条，总 2KB
core.py get <件名>                # ≤8KB，超了截断
core.py status                    # 件数、健康、续点
```

`search` 默认走 FTS5。查询短于 3 字时 trigram 索引没用，自动退成 `LIKE`。加 `--hybrid` 走向量加 FTS 的融合：

- FTS 出 20 个候选，向量出 20 个候选，各给一份排名
- 融合用 RRF，`k=60`，一件的分 = `1/(60+fts排名) + 1/(60+向量排名)`
- 排序分数里还叠了显著度和时间衰减：`bm25 + salience*0.4 + recency`
- 向量这一路失败就静默退回纯 FTS，不报错

先 `search` 再 `get`。一次取不到换词再取，不整目录读。每轮开局先看常驻页，常驻页里没有的再往下搜。

## 向量

`memory/向量.jsonl` 一行一件：`{file, sha1, model, dim, v}`。索引和查询用同一个模型同一维度，绝不混算。

写入时不做向量。`dream` 每天全量重嵌一次（第 9 步），按文件 sha1 判断要不要重算。件数少的时候几秒就跑完；上万件会明显变慢，这是当前实现的已知短板。

嵌入的文本是「标题 + 正文前 800 字」。长件后半段不进向量，这是取舍：向量只负责把候选捞回来，精确判断靠 `get` 读原文。

## 教训与口吻

教训分两头：`dream` 第 5 步扫当天待记，挑出判断可能出错的轮次，写 `运行/待审/<day>.md` 当候选；人确认后把真被推翻的判断写进 `运行/教训.md`。常驻页只带最近五条的标题，开工前扫一眼就够。

口吻自检在插件层：每轮结束看最后一条 assistant 正文，撞禁词、平均句长超 45 字、整句没数字没路径，就记一行到 `运行/口吻自检.jsonl`，合格的也记（`issues` 为空），所以合规率算得出来。`dream` 第 8 步把它汇总成 `运行/报告/口吻-YYYYMMDD.md`，给当天条数、不合格率和最常犯的三条。它只记日志，不插消息，不改回答。

## 评测

`eval.py` 用一份查询集跑三种检索方式，算 recall@5 和 MRR。查询集是 JSON 数组，每项 `{q, expect, kind}`。改 embedding、调 RRF 的 k、调 bm25 权重，都应该先跑一遍这个再上线。

注意 `tools/` 目录里有 `queue.py`，会遮住标准库的 `queue`，`ThreadPoolExecutor` 依赖标准库那个。`eval.py` 在导入前把脚本目录从 `sys.path` 里摘掉了，改这个文件时别把这段删了。

## 备份

三层：本地快照（`dream` 最后一步导一份到 `$DSH_HOME/exports/`）、异地副本、人可读导出（`core.py export`）。只有本地那一层，等于没有备份。导出目录只允许在 `CORE_EXPORT` 下面，越界直接拒绝。
