# 架构

## 两层前端

主会话是决策层：只查、只判、只派。它手里能用的是搜索、记忆、子会话和派单这几样，写文件、跑命令、装东西不在它的工具集里，守卫还会在 `tools/pre-execute` 上再拦一道。

执行层是子会话和本地工人。子会话由 `subagent` 起，跟主会话共享工作区但不共享上下文，带 `parentSession` 标记，守卫放行，全套工具、danger-full-access。干不了的、要等很久的活走本地派单：任务写进 `运行/派单/inbox/`，`xiaomin-delegate` 每 10 秒轮一次，起一个独立子会话，干完把结果推回派单的会话。

这么拆的理由很实际。主会话的上下文要留着做判断和记账，一次拉几十个文件、跑几十分钟的命令会把窗口烧光；执行层的失败也不该把主会话带崩，子会话挂了只丢一份结果，主会话还能重派。

## 七个插件

| 插件 | 管什么 |
|---|---|
| `xiaomin-memory` | 记忆的四个口子。每次调用起一个子进程跑 `mem.py`，15 秒硬超时，输出封顶，绝不把整本账灌进上下文 |
| `xiaomin-jobs` | 一个 60 秒一拍的进程内调度器。任务表是 `运行/jobs.json`，手改文件下一拍就生效，不用重启宿主 |
| `xiaomin-delegate` | 本地派单队列。`inbox` 进、`done` 出，结果推回会话；插件自己不做业务，只负责起会话和收结果 |
| `xiaomin-readonly-preset` | 运行时注册「只读主会话」preset。定义写在 JS 里，是因为 home 层 YAML 预检会扫插件行，配置里出现插件名会被整份隔离 |
| `xiaomin-ctx-guard` | 上下文守卫。每轮结束看一次会话投影里的 `contextPressure`，到窗口 60% 推一条提醒，一个会话只提醒一次，另有 60 秒兜底扫描 |
| `xiaomin-main-guard` | 决策层的墙。顶层会话调 `write`/`edit`/`bash`/`python`/`move`/`publish`/`remove` 直接拒；子会话、`origin=subagent`、`delegationDepth>0` 三种标记任一命中就放行 |
| `xiaomin-sentinel` | 哨兵。监听 `session/event`，每回合把用户首句、助手结尾、工具名和涉及文件攒成一行，追加进 `运行/待记/`，单文件 512 KB 滚动 |

七个插件启动路径都没有副作用：不 spawn、不探端口、不写文件。宿主起不来时逐个摘掉，能定位到是哪一个。

## 哨兵到 dream

```
回合结束 ──▶ 运行/待记/20261106.jsonl ──▶ dream.py（每天 04:10）
                                          ├─ verify      磁盘、索引、域三项对账
                                          ├─ reindex     重建 FTS5 索引
                                          ├─ consume     读待记新行，按天补日报
                                          ├─ vector      补新增或变化的向量
                                          └─ health      写 运行/health.json
```

待记是原料，只读不删，读到第几行记在 `待记/.consumed.json`。日报按天落在 `待记/日报-YYYYMMDD.md`，一行一回：时间、会话、轮次、用户首句、工具数、涉及文件。`health.json` 是后台是否正常的唯一凭据，`mem_status` 末尾会把健康行带出来。整轮预算 55 秒，任何一步抛异常都记进 `steps`，不裸崩。

判定链是「哨兵落料 → dream 消费 → 日报给人看」。判断和心声体只由人写，流水骨架由哨兵补，两边不混。

## 调度器 12 条

`运行/jobs.json` 里现在 12 条。`every` 是固定间隔（秒），`at` 是每天定点，`timeout` 到点 SIGKILL 整组，连败三次进指数退避，错过太久只顺延不补跑一串。

| id | 名字 | 节拍 | 干什么 |
|---|---|---|---|
| `routine` | 日常 | 每小时 | 跑 `进化/工具/日常.py`，维护当日状态 |
| `backup` | 日备份 | 03:10 | `jiyi.py backup`，把记忆机打包 |
| `dream` | 整理 | 04:10 | `dream.py`，体检、索引、消费待记、补向量、写健康表 |
| `radar` | 雷达 | 每周 | 扫外部信号 |
| `voice` | 口吻 | 每周 | 更新口吻样本 |
| `firstaid` | 急救包 | 每周 | `急救.py pack`，打一份可还原的家当包 |
| `archive` | 归档 | 每周 | 把 `$DSH_HOME/sessions` 的会话原文抄进备份 |
| `restore-verify` | 还原验 | 每月 | `急救.py verify`，核对急救包没坏 |
| `offsite` | 远备 | 每周 | `远备.py sync`，往外部位置再放一份 |
| `fun` | 好玩 | 每天 | 收一点轻松的素材 |
| `git-shim` | git 垫片自愈 | 每 30 分钟 | 跑 `fix-git-shim.sh`，端侧 git 不可用，靠垫片兜住命令行调用 |
| `blackbox` | 黑匣子看门 | 每 5 分钟 | 跑 `~/Desktop/小敏黑匣子/看门.sh`，宿主崩了也能留下痕迹 |

调度器一拍只跑一条，同一条在跑就跳过这一拍，所以 12 条不会同时压上来。补跑规则：错过的下一次在 2 倍间隔内就补一次，超了就只顺延。

## 急救包、黑匣子、会话归档

急救包是重装前的家当包。`急救.py pack` 把小敏目录（记忆机、进化、形象、语音、人格草稿、AGENTS.md、开机必读、凭证）和整个 `$DSH_HOME` 打进一个 tar.gz，附 `清单.json`（每个文件的 sha256）、`清单.txt`（人看的）和 `恢复说明.md`。`restore` 只补缺、不覆盖，冲突的另放一处。包里带凭证，属于不可外发的东西。

黑匣子是宿主崩溃时的现场。一个独立脚本每 5 分钟看一次宿主进程，掉了就记日志、留现场，日志在 `~/Desktop/小敏黑匣子/`。它不走 DSH 插件，宿主挂了它还在。

会话归档是会话原文的副本。`归档.py` 只抄 `$DSH_HOME/sessions` 下的 `.zstd` 文件，不动原件，留最近四份，旧的自己删。会话文件解不开也先留着，原件丢了就找不回来。归档进的是 `备份/会话原文/YYYYMMDD/`，和记忆库的备份分开。
