# 提示词：把「主会话不动手」变成规矩

这套骨架装好之后，工具面就有 `delegate`、`mem_*`、`jobs_*` 了。但没有提示词，主会话不会自动去用它们——它会自己读文件、自己改代码，甚至拿 `python`、`terminal` 绕过只读限制。

只读 preset 只封三个入口：`write`、`edit`、`bash`。宿主层注册的 `python`、`terminal_*`、`move`、`publish`、`remove` 删不掉，想绕随时能绕。所以「主会话只查、判、派」这件事只能靠提示词写死。

## 实测边界（DSHM 0.2.1-rc.5，2026-11-05）

| 入口 | 主会话（只读 preset） | 派出去的 subagent |
|---|---|---|
| `write` / `edit` / `bash` | 封 | 有 |
| `python` / `terminal` / `move` / `publish` | 有 | 有 |
| 文件策略 | — | danger-full-access |

结论：主会话要改东西就派；派之前不用猜子会话有没有权限，直接派，受限再回报。拿 `python` 自己绕，只读就成了摆设。

## 贴进 AGENTS.md 的一段

下面是可用的原文，直接放进 `$DSH_HOME/AGENTS.md` 或工作区的 `AGENTS.md`：

```markdown
## 五、派活

主会话只做三件事：下指令、验收、记账。

**主会话不动手。** 改文件、跑长命令、装东西、同步数据、写知识库——一律先派出去。对话里只做查、判、验收。这是硬规矩，不靠自觉。

新会话默认是只读 preset：封的是 `write`/`edit`/`bash` 三个入口，`python`、`terminal`、`move`、`publish` 都还在，想绕能绕过去。只读是约定，不是墙——看见了别拿它当捷径。

派出去的子 agent 不受这条限制：实测手里有全套工具，文件权限是 danger-full-access。所以主会话要改东西，派；不是自己找工具绕。派之前不用猜它能不能干，直接派，受限再回来报。

凡是查、跑、改多文件的活，先派子 agent（`subagent`），派出去就回话，不等它。它回来再汇总、验收。
```

## 怎么启用

DSH 启动时会把 `AGENTS.md` 注入每个会话。放进 `$DSH_HOME/AGENTS.md`，所有新会话都读得到；只想要某个工作区生效，就放那个工作区的根目录。

装了 `dshm-local-jobs` 的话，能独立跑的长任务走本地派单：`delegate` 把任务写进队列，插件每 10 秒轮一次，起独立子会话干完再回报。
