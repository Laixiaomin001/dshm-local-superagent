# 提示词规矩

## 为什么要写这些

模型天然倾向自己动手。上下文里塞着文件路径和工具，它就会去 `cat`、去改、去跑；一轮下来窗口烧掉一半，主会话该做的判断反而没力气做。提示词层面的规矩就是把这个默认扳回来：主会话只查、只判、派，执行层去干。

光靠提示词不够，模型会忘。所以墙上还有一道代码守卫，提示词说一遍，守卫在每次工具调用前再说一遍。两道都失效时，还有第三道：子会话失败的成本比主会话低，派错了重派就是。

## 主会话只做三件事

查：用 `mem_search`、`mem_get`、`session_search`、`web_search` 找依据，单次返回都有上限，要更多就再查一次。判：这件事归谁、要不要花时间、有没有风险。派：写清楚背景、目标、验收标准和目录，交给 `subagent` 或 `delegate`。

主会话不做的事：改文件、跑长命令、装东西、同步数据、写知识库。对话里只留查、判、验收。验收也是看子会话拿回来的证据，不是自己去复跑一遍。

## 守卫拒的七个工具

`xiaomin-main-guard` 挂在 `tools/pre-execute` 上，顶层会话调这七个直接拒：

| 工具 | 干什么 |
|---|---|
| `write` | 写文件 |
| `edit` | 改文件 |
| `bash` | 跑命令 |
| `python` | 宿主内嵌 Python |
| `move` | 移动、改名 |
| `publish` | 往用户可见目录发文件 |
| `remove` | 删文件、删目录 |

拒的时候只回一句「主会话不干活，动手请派子会话」，不带工具参数、不带文件内容。`read`、搜索、记忆、子会话、派单不在名单里，只读的活主会话随便做。

## 子会话豁免

守卫只看调用者是谁。命中任一条就放行：

- 会话头里有 `parentSession`（子会话、派单工人、ralph 轮次都带）
- `origin === 'subagent'`
- `delegationDepth > 0`

子会话拿全套工具和 danger-full-access，不继承主会话的只读 preset。主会话要改东西，派；不是换个工具绕。派之前不用猜它能不能干，直接派，受限再回来报。

## 拆墙文件

`$DSH_HOME/main-guard.off` 存在时守卫整体放行，检查在每次调用前做，建了文件立刻生效，不用重启。这是给「守卫自己挡了正事」留的后门：装插件、修 home、恢复备份这类必须顶层动手的场合，建一个空文件，办完删掉。

墙加高了别硬试。拦下来的是设计，不是 bug。

## 上下文：60% 换页，70% 压缩

单会话上下文超过窗口的 60%（1M 窗口下大约 600K token）就开新会话，把没结的事写进 `mem_store` 再走。`xiaomin-ctx-guard` 每轮结束读一次 `contextPressure`，到 60% 往会话里推一条提醒，一个会话只推一次。

压缩阈值是 70%，在只读 preset 里配成 `thresholdRatio: 0.7`，别再调低。上下文大部分命中缓存，压缩一次会让缓存前缀失效，压得越勤越贵。60% 是换页线，70% 是兜底线，两条线管两件事。

判断「该换页了」还有个体感信号：要想很久才回一句，先怀疑上下文，不是模型慢。换页的收尾动作固定：写续点（卡在哪、下一步、必须知道的参数），写完才算收工。

## 三条硬规矩的由来

只读主会话、写提示词、再加守卫，三样叠着上，是因为单独哪一样都漏。只读 preset 管得住工具集，管不住模型从子会话绕；提示词管得住大多数回合，管不住上下文长了之后的漂移；守卫管得住调用，管不住人想省事直接建个 `main-guard.off`。

所以规矩要写在三个地方，任何一层出问题，另外两层还在。这也是这套东西的底线：能查、能判、能派，剩下的交给执行层，主会话不碰现场。
